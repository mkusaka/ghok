## ⚠️ Breaking changes — review your config and hooks

1. **Comment actions renamed (L1).** `pr.comment` / `issue.comment` are now `pr.comment.create|edit|delete` and `issue.comment.create|edit|delete`, shared with REST and GraphQL. Writes whose subject is unknown (REST `POST .../issues/{n}/comments`, GraphQL `addComment` before node resolution) are `comment.create`. **Update `match.operation`**; to never miss a comment write, also match `comment.*`. `ghok config validate` warns about patterns that match no known action.
2. **`GHOK_NESTED=1` alone no longer bypasses hooks.** Passthrough now also requires a per-invocation token that ghok gives only to its own hooks and resolver. Scripts that set `GHOK_NESTED=1` to skip ghok must call the real gh by absolute path instead.
3. **Hook input is raw.** `argv`, `texts` and `parameters` reach hooks exactly as gh receives them, including credentials (hooks already inherit `GH_TOKEN`; redacting their input only broke secret scanning). **Hooks that forward their input anywhere (Slack, webhooks, files) must set `redactInput: true`.** Logs, `explain`/`normalize` output and terminal messages are still redacted.
4. **An invalid user config in `enforce` mode now stops gh (fail-closed).** If your global `config.yaml` is invalid and declares `policy.mode: enforce`, gh is not run (exit 1, message every time). Previously gh ran without hooks. Observe-mode configs still fail open with a warning. `GHOK_FAIL_CLOSED=1` makes any invalid config fail closed (useful in CI). Run `ghok config validate` after upgrading.

Also: project trust records must be re-created once with `ghok config trust` if you trusted on v0.0.3 or earlier.

## Highlights

- Project `.ghok.yaml`: a broken file or unknown keys only drop the project part (with a note); your user config keeps working.
- `hooks test`: separate Hooks / Policy / FINAL results; `--expect` (final), `--expect-hooks`, `--expect-policy`; reads stdin like the wrapper.
- Node IDs (GraphQL) are resolved to repository/kind only when a rule or hook can act on it, with a 2 s timeout and an on-disk cache; `comment.create` specialises to `pr.comment.create` / `issue.comment.create`.
- `policy.unknownInput` (unreadable request) is separate from `unknownMutation`; stdin analysis waits at most 3 s.
- Per-rule `onUnresolved: deny|ignore`; `runtime.resolveAPI: auto|never`.
- `kill -STOP` of gh no longer strands the wrapper.
