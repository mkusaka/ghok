# Hooks and policy

`internal/policy` is pure; `internal/hooks` executes trusted hook commands. The caller must redact protocol Input before Run, pass the config directory as BaseDir, and enforce pre-hook/policy denials before starting real gh. These packages do not load config, resolve targets, execute real gh, or install shims. ghok is not a security boundary: direct gh/API calls bypass it, and hooks are trusted code.

## Policy decisions and matching

- Actions use Go `path.Match`; dots are ordinary characters. `*` matches all actions, `pr.merge.*` matches direct merge and multi-segment descendants. `pr.merge` is an exact action, not an implicit family prefix. Repository and host globs are case-insensitive; repository `org/*` does not span another slash.
- Criteria are AND; list entries are OR. All operation criteria must hold on the same operation. Commands are token-delimited prefixes of alias-expanded argv; native Origin.Command also identifies command paths after global flags. Level is invocation-wide. Subject.Phase is metadata; config.Match has no phase criterion, and Runner.Select selects Hook.Phase.
- Matches returns definite operation indexes. MatchMaybe returns only candidates with unresolved repository/host constraints. Select includes both; Evaluate conservatively applies may-matching rules and explains uncertainty.
- Operation targets take precedence over ResolvedContext. Missing implicit targets can use context; explicit unresolved fields and GraphQL node-ID repositories cannot borrow the current repository. The resolver must fill those operation targets itself.
- `will-run`, `maybe`, and defensive zero execution values are considered. `not-selected`/`skipped` operations are ignored with evidence in Evaluation.Reasons. PerOp contains considered operations, carrying their original indexes. Invocation-only matches also work for results with no operations.
- Deny dominates audit and allow. Rules are recorded in configuration order; operations in source/index order. UnknownMutation applies to unknown-family non-read operations and unknown/empty effects; default audit. ProtectedUnknown defaults to deny for unclassified writes to protected repositories and any potentially writing operation whose repository is unresolved when a protected list exists. Known writes with known protected targets are not denied implicitly.
- Default mode observe converts would-be denials to audit, including PerOp, and retains WouldDeny. Enforce returns deny. Mutation-free proof, unknown reasons, unresolved targets, and ignored-field evidence remain visible in reasons. Policies do not make API calls or prove server-side merge behavior.

## Hook execution and dependency behavior

- Select is stable priority ascending/configuration order, with dependencies placed before dependents. Disabled hooks and other phases are excluded. Missing/unselected dependencies remain diagnosable: Run reports skipped. Run also skips dependency cycles and duplicate IDs defensively; authoritative validation belongs to config.
- Run caps simultaneous hooks, preserves Select order in Results, and supplies direct dependencies in Input.Previous in dependsOn order. Dependencies must finish before launch. A failed dependency skips non-optional dependents; optional dependents can receive failed results. Dependency pre-denials trigger the global denial short-circuit.
- Pre denial cancels pending hooks and running process groups. Canceled hooks still apply onError; the final result cannot be changed back to allow. Message uses the first effective denial in selection order (message, then reason, then error), not completion order. Post responses retain their reported decision, but all post effective decisions/aggregation are abstain.
- Relative command paths containing `/` resolve against BaseDir; bare names search the hook's effective PATH without changing the wrapper environment. The command is not evaluated by a shell. A command named `gh` may resolve to a shim; GHOK_NESTED=1 is always supplied, but bypass also requires the integrator's valid invocation token in Runner.Env. The CLI creates and removes the private hash-named token file around its helpers.
- Runner.Env is the base environment (nil uses os.Environ), Hook.Env overrides it, and GHOK_EVENT/EVENT_ID/HOOK_ID/NESTED override both. GHOK_NESTED_TOKEN is taken only from the base environment, not Hook.Env. RealGh, when set, overrides GHOK_REAL_GH. Now and Redact callbacks must be safe for concurrent invocation. Redact defaults to identity and applies to diagnostics, reason, and message; it does not sanitize Input.
- Stdin is a single JSON Input plus newline and EOF; schemaVersion/event/hookId are set by Run. Exit zero with empty/whitespace stdout abstains. A single JSON response accepts schemaVersion absent/0/1 and allow/deny/abstain only. Invalid JSON, another document, trailing garbage, unknown decisions/versions, or stdout overflow are invalid-response. Overflow is rejected even when the captured prefix is valid JSON, because the unseen suffix cannot be validated. Nonzero exit/spawn failures are error regardless of stdout. Optional missing/non-executable commands are skipped.
- Output writers retain bounded bytes and drain excess to avoid blocking children. MaxOutputBytes, when positive, bounds each stream; zero/negative uses separate stdout/stderr defaults. Stderr gets a truncation marker. ExitCode is -1 for unstarted/signaled processes; timeout/cancellation outcomes are independent of the observed child exit code (a TERM handler may exit zero).
- Defensive defaults exported by hooks: DefaultTimeout=10s, DefaultConcurrency=1, DefaultMaxOutputBytes=1 MiB, DefaultMaxStderrBytes=64 KiB, DefaultPreOnError=deny, DefaultPostOnError=ignore. Errors/timeouts/invalid responses/cancellation apply pre onError deny/allow/ignore. Post always ignores effective decisions, including an invalid onError deny.

## POSIX verification and platform limits

Each hook starts in its own process group (Setpgid). Timeout/parent cancellation sends SIGTERM to the group, then SIGKILL after TerminationGrace=500ms even if the leader exits early. The direct child is always waited. Cmd.WaitDelay bounds inherited stdin/stdout/stderr pipe-copy lifetime after leader exit; retained pipes on normal exit cause error and a group SIGKILL. Descendants that deliberately leave the process group are outside this cleanup guarantee; hooks are non-interactive trusted processes.

Hermetic shell fixtures exercised nested background grandchildren, TERM traps with wait/reaping, group disappearance via `kill(-pgid, 0) == ESRCH`, timeout, parent cancellation, dependency stdin, priority, parallel file barriers, denial cancellation, bounded output, executable lookup, and redaction on macOS. A standalone Go smoke invocation exercised real allow/deny/timeout scripts and protected unresolved policy decisions. Tests use temporary HOME/XDG and fake scripts, never GitHub/network/user config. Shell is a test-only dependency.

The same Unix implementation and POSIX shell fixtures target macOS and Linux; no platform-specific API beyond Setpgid/signals is used. Linux runtime behavior was not executed in this macOS worker; cross-build results are recorded in the final report. No cli/cli source was needed or read for this area: these packages consume ghok's shared normalized-model/config/protocol contracts, rather than interpret gh CLI arguments. Unsupported: Windows, interactive hooks, process cleanup after a hook deliberately escapes its group, and automatic secret redaction of Input.
